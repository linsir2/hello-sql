## 1. 项目目录总览

```text

├─ storage/             # 模块 B：存储层（页式存储 + 缓存 + 目录 + 行级 API）
│   └─ __init__.py      #   对外入口：DatabaseServer / Storage（由 B 实现）
│                       #   B 内部可自行拆分：pager.py / cache.py /

│   └─ __init__.py      #   对外入口：Runner(server, parse)（由 C 实现）
```

## 2. 三人分工一览

| 角色 | 目录 | 对外入口 | 交付物 |
|---|---|---|---|
| A：编译 | `compiler/` | `parse(sql) -> Statement` | 词法 Token 流、AST、语法错误（带位置） |
| B：存储 | `storage/` | `DatabaseServer` + `Storage` | 页式存储 + 缓存 + 目录 + 行级 CRUD，重启可持久 |
| C：运行 | `runner/` | `Runner(server, parse)` | 语义检查、执行计划、算子执行、REPL、QueryResult |

## 3. 说明书条目 → 负责人

| 说明书要求 | 负责人 | 落点 |
|---|---|---|
| 规则定义（词法 / 语法 / 语义规则、关键字表、符号表、常量表示） | A | `compiler/`（目录实现不归 A） |
| 词法分析（Token 四元式 `[种别码, 词素, 行, 列]`、非法字符报错带位置） | A | `compiler/lexer` |
| 语法分析（LL(1) → AST、输出语法树、语法错误带位置 / 期望符号） | A | `compiler/parser` |
| 语义分析（表 / 列存在性、类型、列数 / 列序检查） | C | `runner/`，调 `storage.describe()` |
| 执行计划生成（CreateTable / Insert / SeqScan / Filter / Project 等算子） | C | `runner/plan`（内部表示，可选 JSON / S-表达式打印） |
| 结果输出与测试（Token → AST → 语义 → 计划逐级输出 + 错误提示） | C | `runner/REPL` + `tests/golden_sql.py` |
| 页式存储设计（页结构、页分配 / 释放、页读写） | B | `storage/pager` |
| 缓存机制（LRU / FIFO、命中统计、刷新与持久化） | B | `storage/cache` |
| 统一存储接口、数据表 ↔ 页映射 | B | `storage/Storage` 对外方法 |
| 系统目录（catalog）：查询结果形状（TableInfo/ColumnDef）定义在 contracts；查询接口签名在 contract-v1.md 第 3 节；真实目录数据、初始化 / 持久化 / 注册 / 注销 / 查询实现全归 B | B 实现；C 只读（describe / list_tables）；A 不碰 | `storage/catalog`（B 内部自建）+ `contracts/storage.py` |
| 执行算子实现（CreateTable / Insert / SeqScan / Filter / Project） | C | `runner/executor` |
| 记录 Row ↔ 页 Page 序列化、空闲页列表、表的扩展与回收 | B | `storage/engine` |
| 系统架构与数据流定义 | 三人共同 | `contracts/` + `docs/` |
| 综合测试与验收 | C 汇总，三人各交日志 | `main.py` + golden |

Catalog 一句话归属：**A 不碰（只产出 AST）；B 全包（真实数据的初始化 / 增删 / 持久化 / 查询实现）；C 只读（describe / list_tables）。**

补充：catalog 不是给别人直接调的接口，而是 B 的内部记忆——describe / list_tables /
create_table / drop_table 等都靠它查、注册表结构；重启后 B 靠它恢复元数据。
别人只通过公开方法使用它，不需要直接碰 catalog。

## 4. 数据流总览（按说明书阶段串起来）

```text
用户输入 SQL
  ① C：REPL 读入一行，交给 parse
  ② A：词法分析 → Token 流 [种别码, 词素, 行, 列]（非法字符报错带位置）
  ③ A：语法分析（LL(1)）→ AST（语法错误带位置 / 期望符号）
  ④ C：语义分析 → 调 B 的 describe() 查目录，检查表 / 列存在性、类型、列数
  ⑤ C：AST → 逻辑执行计划（CreateTable / Insert / SeqScan / Filter / Project…）
  ⑥ C：逐算子执行，每个算子调用 B 的表级方法
  ⑦ B：底层执行（页读写 → 缓存 LRU → 行↔页序列化 → 目录更新 → 落盘）
  ⑧ C：组装 QueryResult → REPL 打印表格 / 行数 / 错误
```

每个交接点的产物都是确定的：

| 交接 | 产物 | 类型定义位置 |
|---|---|---|
| A → C | Statement（AST） | `contracts/ast.py` |
| C → B | 8 个表级调用 / 5 个库级调用 | `docs/contract-v1.md` 第 3 节 |
| B → C | Row / TableInfo | `contracts/storage.py` |
| C → REPL / 测试 | QueryResult | `contracts/result.py` |
| 三方 | 错误（错误码 + 消息） | `contracts/errors.py` |

## 5. 典型语句的数据流示例

### SELECT name, age FROM users WHERE age >= 18;

```text
C 读入 SQL
→ A 词法：SELECT / name / age / FROM / users / WHERE / age / >= / 18
→ A 语法：SelectStmt(columns=(name, age), table=users, where=age >= 18)
→ C 语义：storage.describe("users") 校验列存在、类型
→ C 计划：SeqScan(users) → Filter(age >= 18) → Project(name, age)
→ C 执行：
     for row_id, values in storage.scan("users"):   # B 给行
         if eval(age >= 18):                        # C 算 WHERE
             out.append((name, age))                # C 投影
→ C 输出：QueryResult(columns=(name, age), rows=…)
```

### UPDATE users SET age = 19 WHERE name = 'alice';

```text
→ A 语法：UpdateStmt(...)
→ C 语义：describe 校验 name / age 列
→ C 执行：
     matched = []                                   # 先收集，不边扫边改
     for row_id, values in storage.scan("users"):
         if values[name] == 'alice':
             matched.append(row_id)
     for rid in matched:                            # 逐个整行替换
         storage.update_row("users", rid, new_values)
→ C 输出：QueryResult(affected_rows=1)
```

### 数据库语句

```text
CREATE DATABASE shop;   → server.create_database("shop")
USE shop;               → storage = server.connect("shop")   # C 换连接
DROP DATABASE shop;     → C 先拦“当前库”，再 server.drop_database("shop")
```

## 6. 交接链与红线

```python
# main.py（装配层，唯一同时 import 三家的地方）
from compiler import parse           # A 交付
from storage import DatabaseServer   # B 交付
from runner import Runner            # C 交付

server = DatabaseServer("data")      # 自动创建默认库 main
runner = Runner(server=server, parse=parse)
runner.repl()
```

- `compiler`、`storage`、`runner` 之间禁止互相 import，各自只能 import `contracts`；
- A 不知道表存不存在；B 不认识 SQL / AST；C 不知道 B 的文件格式；
- 方法签名在各自 `__init__.py` 定义（B 实现时以 `contract-v1.md` 第 3 节为准）；
- 契约改动需三方同意并同步 golden，当前版本 V1.1；
- 集成验收 = `main.py` 装配后按 `tests/golden_sql.py` 37 条顺序跑通。
